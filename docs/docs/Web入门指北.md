# Web/Agent 组 2026 春招入门指北

Web 不只是网页，Agent 也不只是一次模型调用。一个真正可用的 AI Native 应用，往往同时包含界面、服务端、数据库、模型、工具、部署和持续迭代。Web/Agent 组不再把前端、后端和 AI 划成互不相干的方向，而是希望大家从一个能运行的小项目开始，逐渐理解完整的软件系统。

你可以做一个网页、写一个接口、接入一个模型，也可以研究 Agent 如何使用工具、管理上下文和完成长任务。重要的不是先给自己贴上“前端”或“后端”的标签，而是持续动手，把一个想法做成真实可用的东西。

我们不要求你已经熟练掌握某个框架。只要接触过一门编程语言，能够借助 AI 完成基础开发和调试，并愿意主动查资料、验证结果、理解自己写出的代码，就可以从这里开始。

## 如何使用这份指北

下面是一张知识地图，不是必须按顺序通关的课程表。遇到感兴趣的任务时，先做起来，再回到对应章节补足知识。你不需要一次学完所有内容，也不需要为了“准备充分”而连续看完许多教程。

推荐的学习方式是：

1. 选择一个规模足够小、可以展示的项目。
2. 用文档、搜索和 AI Coding Agent 辅助开发。
3. 亲自运行、测试并解释关键代码，不能只以“AI 说可以”为准。
4. 记录遇到的问题、失败方案和最终取舍，再继续迭代。

## 计算机与开发基础

如果你刚开始学习编程，可以先建立对计算机世界的整体认识，不必一开始钻进所有细节。

- [计算机科学速成课](https://www.bilibili.com/video/av21376839/)：用直观的方式了解计算机科学的主要领域。
- [CS50](https://cs50.harvard.edu/x/)：从编程和问题求解开始的计算机科学入门课。
- [CS 自学指南](https://csdiy.wiki/)：适合在需要深入某个方向时查找课程。

无论使用哪种语言或工具，都建议尽早熟悉这些通用能力：

- Git 只需先掌握日常开发和团队协作所需的基础：创建提交、查看 diff、创建分支、合并或变基、解决冲突，以及从远程仓库拉取和推送代码。
- 推荐通过交互式教程 [Learn Git Branching](https://learngitbranching.js.org/) 练习分支和提交；不必一开始深入 Git 的内部实现或复杂命令。
- 在团队项目中遵循清晰的提交信息和分支协作流程，提交前检查改动，合并前运行必要的测试。
- 使用终端完成文件操作、运行程序和查看日志。
- 学会阅读报错、官方文档和英文技术资料。
- 理解变量、函数、数据结构、模块、异步与基本调试方法。

## 从网页到完整应用

学习 Web 最直接的方法，是做出一个可以被使用的应用。你不必先决定自己属于前端还是后端，而可以沿着一次用户操作经过的完整链路逐步学习。

### 浏览器与界面

HTML 描述内容结构，CSS 控制布局与视觉表现，JavaScript/TypeScript 负责交互和状态。入门阶段先用原生技术理解浏览器，再根据项目选择 React、Vue 等框架，不需要同时学习多个框架。

建议掌握：

- 语义化 HTML、常用 CSS 布局和响应式设计。
- JavaScript 基础、DOM、事件、模块和异步请求。
- 表单、加载状态、错误提示和基本可访问性。
- 浏览器开发者工具，以及网络请求和控制台的调试方法。

主要资料：[MDN Web Docs](https://developer.mozilla.org/zh-CN/docs/Learn_web_development)、[现代 JavaScript 教程](https://zh.javascript.info/)。

### 服务、数据与网络

当应用需要保存数据、处理权限或调用外部服务时，就需要服务端和数据库。可以继续使用 JavaScript/TypeScript，也可以选择你已经熟悉的 Python、Go、Java、Rust 等语言。语言不是重点，先把一次请求如何进入系统、处理数据并返回结果弄清楚。

建议掌握：

- HTTP、URL、请求方法、状态码、JSON 和 Cookie。
- API 的设计、输入校验、错误处理和日志。
- SQL、关系型数据库、表结构、查询和事务的基础概念。
- 用户认证、权限检查、密码和密钥的安全存储。
- 环境变量、构建、部署、域名和 HTTPS。

可以从一个带登录和数据持久化的小应用开始，例如笔记、任务管理、资料收藏或组内工具。数据库入门也可以尝试 [SQL Murder Mystery](https://mystery.knightlab.com/)。

### 工程质量

能运行只是起点。随着项目变大，你还会遇到代码组织、多人协作和线上故障。此时再按需要学习类型系统、测试、代码检查、CI/CD、缓存、性能、安全和可观测性，比提前背诵大量概念更有效。

## 从模型调用到 AI Native 应用

在 Web 应用中接入大模型，通常从一次模型 API 调用开始。先完成输入、输出和流式展示，再逐步增加结构化输出、外部数据和工具。不要急着把所有功能都包装成 Agent。对于步骤固定、结果可验证的需求，普通程序或工作流往往更简单可靠。

建议了解：

- 模型的输入输出、上下文窗口、Token、采样和延迟。
- System Prompt、用户输入和外部数据各自承担什么职责。
- 流式响应、结构化输出以及失败重试。
- RAG 的基本流程：检索相关资料，将必要上下文提供给模型。
- Prompt Injection、隐私泄露、越权调用和不可信模型输出等风险。
- 成本、速度和效果之间的取舍。

一个合适的起步项目可以是文档问答、资料整理、信息抽取或带 AI 辅助的 Web 工具。重点不是套用热门名词，而是让用户能看见过程、处理失败，并判断结果是否可信。

## Agent：让模型采取行动

Agent 的核心不是“更长的 Prompt”，而是让模型在一个循环中观察当前状态、决定下一步、调用工具、读取结果，直到完成任务或停止。一个最小的 Agent Loop 可以理解为：

1. 接收目标和当前上下文。
2. 模型判断是直接回答，还是调用某个工具。
3. 程序执行工具并把结果返回给模型。
4. 模型根据新信息继续行动，或给出最终结果。

在此基础上，可以继续研究以下主题。

### 工具与环境

工具让 Agent 能够搜索资料、读写文件、运行代码、访问数据库或调用业务 API。工具接口要有清晰的名称、参数和返回值，并限制权限、执行时间和影响范围。对删除数据、发布内容、付款等高风险操作，应设置确认或审批。

### 上下文与记忆

上下文不是越多越好。需要区分当前任务信息、工具结果、项目规则和长期记忆，并通过选择、摘要或检索控制输入规模。长期记忆也不能只是无限保存对话，而应考虑写入条件、更新方式、冲突处理和删除机制。

### 规划与状态

复杂任务可能需要拆分步骤、记录进度并在失败后调整方案。计划应该服务于行动，而不是生成后永远不变。程序还需要明确最大轮数、超时、取消、重试、幂等和恢复策略，避免 Agent 无限制循环或重复执行有副作用的操作。

### 评测与可观测性

Agent 的输出具有不确定性，只凭一次演示无法判断是否可靠。应该保存模型请求、工具调用、耗时、Token 和错误信息，建立一组有代表性的任务，反复评测完成率、结果质量、成本和延迟。修改 Prompt、模型或工具后，用相同任务做回归测试。

### Harness Engineering

Agent 的能力不仅取决于模型，也取决于它工作的环境。清晰的项目说明、可发现的工具、快速反馈、自动测试、权限边界和可恢复的任务状态，共同构成支持 Agent 工作的 Harness。研究 Agent 时，不仅要改 Prompt，也要思考怎样让正确行动更容易、错误更早暴露。

## AI Coding Agent

Claude Code、Codex、Pi 等 AI Coding Agent 可以阅读项目、搜索代码、调用工具、修改文件并运行测试。我们既会使用它们完成项目，也会把它们当作可以研究的 Agent 系统。

可以关注：

- Agent Loop 如何组织模型与工具之间的交互。
- 项目指令和上下文如何影响结果。
- 长任务如何规划、压缩上下文、保存状态并恢复。
- 如何设计代码搜索、补丁、终端和浏览器等工具。
- 如何通过测试、静态检查、代码审查和权限控制建立反馈。
- 多 Agent 协作在哪些任务中有价值，又会引入哪些协调成本。

使用 AI Coding Agent 时，可以大胆让 AI 参与探索和实现，但必须对最终结果负责：检查 diff，运行程序和测试，核实引用与依赖，并能解释关键设计。AI 的价值不是替你跳过理解，而是让你能够更快地探索、更早地做出完整项目。

## 可以探索的方向

这张知识地图没有唯一终点。你可以根据兴趣选择：

- 做一个体验完整的 Web 产品，继续深入交互、工程化与部署。
- 为现有应用加入模型能力，研究流式交互、RAG 和结构化生成。
- 实现一个最小 Agent，逐步增加工具、记忆、规划和评测。
- 阅读并修改开源 Coding Agent，理解它的运行循环和上下文管理。
- 改进 Agent 的 Harness，让它更容易发现问题、验证结果和完成长任务。

不必等到掌握整张地图才开始。先选择一个真实问题，做出第一个可运行版本，再让问题带着你学习下一部分。
